# ADR-0003：混合端到端回归

| 属性 | 值 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-09-14 |
| 决策者 | DSH Maintainer |
| 关联文档 | [测试策略](../04-test-strategy.md)、[Gerrit 与 Jenkins](../02-gerrit-and-jenkins.md) |

## 上下文

DSH 的发布风险主要出现在终端用户旅程：启动会话、调用工具、读写文件、Web 交互、插件发现和插件基本能力。单元测试或 HTTP 端口就绪不能证明这些旅程可用。

`dsh-tui` 被确定为后期 feature，当前不属于 CI/CD 门禁和发布回归范围。

完全依赖真实 DeepSeek API 会受到密钥、网络、限流、费用和非确定输出影响；完全使用 Mock LLM 又无法验证真实协议、鉴权、流式响应和供应商兼容性。

## 决策

1. 采用分层自动化回归，而不是用单一 UI 套件覆盖全部风险。
2. 每个 Change 必须执行确定性、无外部密钥的 Mock LLM 用户旅程；发布 candidate 在 staging 额外执行小规模真实 DeepSeek 验证。
3. 核心 CLI/Agent 流程优先使用现有 `dsh-headless`；Web 和浏览器终端用户旅程使用 Playwright headless。
4. 每个必需场景在版本化 catalog 中声明所属层级、平台、驱动、外部依赖、超时和证据。必需场景 missing、skip 或首次失败后重试通过，都不得被统计为干净绿色。
5. 真实模型断言稳定不变量，如退出码、工具调用结果、文件副作用和响应结构；不得依赖完整自然语言逐字匹配。
6. 发布前至少覆盖 Harness 核心基本功能和每个随发布插件的一条代表性用户旅程。

## 后果

正向后果：

- 高频变更获得快速、确定且低成本的回归反馈。
- 发布门禁仍能发现 Mock 无法覆盖的真实供应商集成问题。
- headless 与浏览器分别覆盖 Agent/工具闭环和终端用户界面，失败证据更容易定位。
- catalog 能防止插件已打包但其测试未运行的“假绿”。

代价与风险：

- 需要维护 Mock 协议、测试夹具、隔离 profile 和三类驱动。
- Playwright 选择器、浏览器终端状态和真实模型预算需要持续治理。
- 第三方服务能力不能全部在 presubmit 中真实复现，需要契约测试和发布阶段补偿。

## 被否决的替代方案

- **只跑单元测试**：无法覆盖安装、装载、配置与用户交互边界。
- **所有回归都调用真实模型**：慢、贵且不稳定，不适合作为每个 patchset 的 Verified 条件。
- **只做浏览器 E2E**：无法充分覆盖 headless Agent、工具调用和文件副作用。
- **允许 flaky retry 变绿**：会掩盖发布风险并使门禁失去可信度。

## 实施约束

- 测试使用临时 `DSH_HOME`/profile，不得读取或修改开发者及生产用户状态。
- Playwright 在共享 CI 环境默认单 worker，失败时保存 trace、截图、视频和服务日志。
- 真实 DeepSeek 凭据只在受限 staging Job 注入；日志必须脱敏并限制 token、请求数、超时与预算。
- 测试证据与 candidate digest 绑定并上传 Nexus evidence 仓。
